# GPT 작업 브리프 — 골목 시술소 (마사지 샵 도트 타이쿤)

이 문서는 GPT가 처음 읽는 파일이다. 읽은 뒤 `docs/GAME_DESIGN.md`, `docs/ASSET_SPEC.md`, `docs/LORE.md` 순서로 본다.

## 1. 프로젝트 한 줄

판타지 교역도시 뒷골목의 작은 마사지 시술소를 키우는 **도트 그래픽 경영 시뮬레이션**.
가게를 넓히고, 직원을 뽑고, 능력치를 올리고, 평판을 쌓아 손님층을 바꾼다. 웹 브라우저(GitHub Pages)에서 돈다.

## 2. 역할 분담

| 담당 | GPT | Claude |
|---|---|---|
| 이미지 (스프라이트, 초상화, 배경, UI 아이콘) | ● | |
| 구체 기획 (이벤트 텍스트, 대사, 밸런스 표, 인물별 훅의 선택지/결과) | ● | |
| 데이터 파일 채우기 (`src/data/*.js`) | ● 제안 → | ● 반영·검증 |
| 엔진 코드 (`src/*.js`, `index.html`, `style.css`) | | ● |
| 에셋 규격 (`docs/ASSET_SPEC.md`) 변경 | 요청 | ● 결정 |

GPT는 코드를 고치지 않는다. 코드가 바뀌어야 하는 기획이면 "Claude에게 요청" 항목으로 적어서 넘긴다.

## 3. 톤 (중요)

원작 챗봇 설정은 19+였지만 **이 게임은 전연령 경영 시뮬**이다.

- 성인 요소는 뺀다. 남기는 건 **은유적인 암시**뿐이다. 예: "칸막이 너머로 소리가 샌다", "체면 있는 손님은 뒷문으로 온다", "소문이 커지면 감찰이 온다".
- 신체 노출, 성적 묘사, 성적 대가 구조는 넣지 않는다. 이미지도 마찬가지.
- 긴장감의 원천은 "참음"이 아니라 **경영의 선택**으로 옮긴다. 방음벽을 달면 소문은 줄지만 오해·질투 이벤트도 줄어드는 식의 트레이드오프.
- 인물 관계는 호감/신뢰 단계까지. 연인 엔딩이나 침실 묘사는 없다.
- 등장인물은 전원 성인.

## 4. 지금 있는 것 (뼈대)

브라우저에서 `index.html`을 열면 바로 돈다. 스프라이트 파일이 없어서 지금은 색 블록 인형으로 표시된다.

- 하루 루프: 09:00 개점 → 낮/저녁/심야 → 24:00 마감 → 정산 → 다음 날
- 손님 생성 → 대기실 → 빈 시술실 + 빈 직원에게 자동 배정 → 시술 → S/A/B/C 판정 → 대금·평판·소문
- 직원 4능력치(손기술/감각/체력/친절), 피로, 경험치·레벨
- 배치: 레이나를 접수대(손님 유입↑) 또는 조향실(향유 생산)에 둔다
- 확장 8종, 향유 2종 구매, 구인(매일 3명 갱신), 해고
- 평판 4단계(무명→입소문→단골 가게→골목 명소)에 따라 손님층·메뉴 해금
- 소문 게이지 → 70 이상이면 감찰 이벤트
- 엘리트 5인: 직원 2(레이나, 네르), 손님 3(세르피나, 이브레아, 카샤). 관계도 0~100
- **관계 탭**: 엘리트와 대화(하루 1회, 관계 단계별 주제·선택지), 선물(향유), 출장(손님)
- 엘리트 훅 12종: 선택지 이벤트. 전속 계약, 지정 시술소, 측정 퀘스트, 월하향, 꼬리 결, 정식 시술사, 위생 감찰 등
- 단골 손님, 구인 특성 5종, 확장 14종, 목표(마일스톤) 15개, 칸막이 엿듣기·질투 이벤트
- 하루 이벤트 8종
- 저장: 브라우저 localStorage (버전 마이그레이션 있음)

## 5. GPT에게 요청하는 것 (우선순위 순)

### 5-1. 이미지 (1차분)
`docs/ASSET_SPEC.md`의 규격대로. 파일명이 정확해야 엔진이 자동으로 읽는다.
1. 캐릭터 워킹 스프라이트 6장: `char_P, char_A, char_B, char_C, char_D, char_E` (16×24, 4프레임)
2. 손님 스프라이트 10장: 종족 5 × 성별 2
3. 초상화 5장: `face_A_2` ~ `face_E_2` (64×64, 평소 표정)
4. 1층 평면도 배경 `floor1.png` (384×216) — 방 좌표는 ASSET_SPEC 참조
5. UI 아이콘 시트

### 5-2. 기획 (1차분)
`docs/GAME_DESIGN.md`의 "GPT가 채울 것" 항목.
1. **대화 주제 확장**: `src/data/dialogues.js` 형식으로 인물당 단계별 2~3개. 지금은 4개뿐
2. 훅 이벤트 12종의 문장 다듬기 + 하루 이벤트 신규 10종
3. 손님 대사 풀 확장 (입장/만족/불만/단골/엿듣기 각 10개 이상, 종족별 한 줄)
4. 밸런스 표: 1~30일차 목표 수입·평판 곡선. 현재 수치는 `src/data/config.js`
5. 후반 콘텐츠·마일스톤 추가 제안

### 5-3. 산출물 형식
- 이미지: PNG, 투명 배경(배경 제외), 규격 픽셀 그대로(업스케일 금지). 파일명은 ASSET_SPEC과 일치.
- 텍스트 데이터: `src/data/*.js` 형식에 맞춘 JS 객체 조각, 또는 표. Claude가 파일에 반영한다.
- 기획서: 마크다운. 수치는 표로.

## 6. 작업 규칙

- 파일명에 한글·공백을 쓰지 않는다 (GitHub Pages 주소가 깨진다).
- 인물 코드 A~E 는 고정이다. 이미지·대사·데이터 전부 이 코드로 잇는다.
- 챗봇 쪽 외형 설정(머리색, 의상, 눈색)은 그대로 쓴다. `docs/LORE.md` 참조. 도트로 줄이되 식별 요소(레이나 사이드 땋은 머리, 네르 고양이 귀·꼬리, 세르피나 하이포니테일·제복, 이브레아 안경·보라 카디건, 카샤 갈색 피부·은발·붉은 드레스)는 남긴다.
- 모르는 건 묻기보다 합리적 기본값으로 정하고 "이렇게 잡았다"고 적는다.

## 7. 폴더 지도

```
index.html          진입점
style.css
src/data/           ← GPT가 채우는 데이터 (config, characters, menu, upgrades+milestones, customers, events, dialogues)
src/                엔진 (util, state, sim, render, ui, main)
assets/manifest.js  에셋 경로 목록
assets/sprites/     캐릭터·손님·초상화 PNG   ← GPT 이미지
assets/bg/          배경 PNG                  ← GPT 이미지
assets/ui/          아이콘                    ← GPT 이미지
docs/               이 문서들
```
