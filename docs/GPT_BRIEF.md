# GPT 작업 브리프 — 골목 시술소 (마사지 샵 도트 타이쿤)

이 문서는 GPT가 처음 읽는 파일이다. 읽은 뒤 `docs/ASSET_SPEC.md` → `docs/LORE.md` → `docs/GAME_DESIGN.md` 순서로 본다.

> **2026-10-13 UI·UX 인수 갱신:** 사용자가 승인한 방향은 화면 전체가 어우러진 도트 게임 UI다. 최신 콘텐츠(`a641941`)를 반영한 구현 기준은 [UX v3](ux/README.md)와 [기능 연결·검수](ux/IMPLEMENTATION_HANDOFF.md), 목업은 `docs/ux/previews/v3/`에 있다. 아래 4장의 화면 구조는 현행 앱 설명이며 유지할 디자인이 아니다. 플레이 HUD의 게임 제목·한자 로고·영문 부제는 사용자 요청으로 제거하고, 화폐·아이템·버튼·창도 도트로 통일한다. 게임 코드는 기존 역할 분담대로 Claude가 구현한다.

## 1. 프로젝트 한 줄

판타지 교역도시 뒷골목의 작은 마사지 시술소를 키우는 **도트 그래픽 경영 시뮬레이션**.
가게를 넓히고, 직원을 뽑고, 능력치를 올리고, 평판을 쌓아 손님층을 바꾼다. 다섯 명의 엘리트 인물과 대화하며 관계를 쌓는다. 웹 브라우저(GitHub Pages)에서 돈다.

## 2. 역할 분담 (고정)

| 담당 | GPT | Claude |
|---|---|---|
| **도트 스프라이트·초상화·배경·아이콘** | ● | |
| **UX**: 화면 배치, 정보 우선순위, 패널·탭·모달 구성, 색·폰트, 모바일 대응 제안 | ● 제안 | ● 구현 |
| 대화·이벤트·대사·세계관 텍스트 | | ● |
| 밸런스·수치·시스템 설계 | | ● |
| 엔진 코드 전부 | | ● |

GPT는 텍스트 콘텐츠(대사, 이벤트, 설정)를 쓰지 않고 코드를 고치지 않는다. UX는 **제안서(마크다운 + 목업 이미지)** 로 넘기고 Claude가 구현한다.

## 3. 톤 (이미지에도 적용)

- 전연령 경영 시뮬. 성인 요소 없음. 노출·선정 이미지 금지
- 따뜻한 등불 톤의 판타지 뒷골목. 아늑하고 조금 낡은 가게
- 인물 외형은 `assets/ref/ref_A~E.webp` 참고 그림과 `docs/LORE.md` 기준. 도트로 줄여도 식별 요소는 남긴다
- **참고 그림을 그대로 쓰거나 축소·필터·트레이싱하는 것은 금지.** 보고 새로 찍는다 (`assets/ref/README.md`)
- 표정은 인물 성격을 따른다. 이브레아의 기쁨은 밝은 웃음이 아니라 건조한 만족, 레이나는 옅은 홍조와 비껴간 시선, 카샤는 반쯤 감은 눈

## 4. 지금 게임이 어떻게 생겼나 (UX 제안의 출발점)

현재 화면은 Claude가 기능 위주로 짠 임시 레이아웃이다. 바꿔도 된다. 단, 아래 **정보와 조작**은 어딘가에 반드시 있어야 한다.

### 4-1. 화면 구조 (지금)
```
┌─ 상단바: 가게 이름 · N일차 · 시간대 · 시각 ·· 소지금 · 평판(단계+수치) · 소문 ·· 속도 ⏸/1x/2x/4x
├─ 왼쪽 큰 영역: 캔버스 384×216 (1층 평면도, 정수 배율 확대)
│    접수대 / 대기실 / 베드 1~8 (4열×2행) / 조향실 / 2층 계단. 사람들이 걸어 다님. 시술 진행 바
├─ 왼쪽 아래: 로그 (시각 + 한 줄 텍스트. 좋음=초록, 나쁨=빨강, 이벤트=금색)
└─ 오른쪽 패널 300px, 탭 8개 (지금은 두 줄로 접힘 — UX 과제):
     가게   오늘 수입/지출/시술/이탈, 베드·대기·직원 정원 현황, 단골 수, 메뉴 4종, 업적 진행 상위 4개, 장부 7일
     직원   직원 카드(능력치 4, 특성, 피로 바, 경험 바, 배치 버튼: 접수/조향/시술/휴식, 해고, 수건 사용), 정원 N/M, 구인 3~5명(고용)
     확장   업그레이드 20종 (이름, 가격, 효과, 잠금 조건, 구매)
     향유   진정/온열 재고와 구매(1병/5병), 월하향(해금 시), 조향실 상태
     던전   심연구 탐사(깊이 1~3층 선택, 파티 최대 3명 선택, 출발), 재료 7종(팔기), 제작 레시피 10종, 소모품 4종(사용)
     관계   엘리트 직원 + 손님 카드: 초상화 자리, 관계 바(0~100, 단계명), 설명, 훅/영입 조건, 버튼: 대화/선물/출장
     업적   76개, 분류 6개(가게/평판/확장/향유/던전/관계), 진행 바, 숨겨진 업적 ???, '영입 조건' 태그
     설정   가게 이름, 저장, 오늘 마감, 새 게임, 누적 통계
   모달: 하루 이벤트(확인), 스토리 이벤트(선택지 2~3), 대화(인사 → 주제 선택 → 선택지 → 반응), 마감 정산
   토스트: 업적 달성 시 화면 하단 중앙에 2.6초
```

### 4-2. 자주 하는 조작 (우선순위)
1. 속도 조절 / 일시정지 (항상 보여야 함)
2. 대기실·시술실 상황 한눈에 보기 (누가 기다리고, 어느 방이 비었는지)
3. 직원 배치 바꾸기 (특히 레이나 접수↔조향)
4. 확장 구매, 향유 구매
5. 관계 탭에서 대화하기 (하루 1회라 "오늘 가능한 인물"이 보이면 좋다)
6. 이벤트 선택지 읽고 고르기
7. 던전 파티 짜서 보내기 (오전에 보내야 당일 복귀) · 재료로 제작
8. 업적 진행 확인

### 4-3. 모바일
현재는 800px 이하에서 패널이 캔버스 아래로 내려간다. 세로 화면 UX 안이 필요하다.

## 5. GPT에게 요청하는 것

### 5-1. 이미지 1차분 (규격은 `docs/ASSET_SPEC.md`, 파일명 정확히)
1. 캐릭터 워킹 스프라이트 6장: `char_P, char_A, char_B, char_C, char_D, char_E` (64×24, 4프레임)
2. 손님 스프라이트 10장: 종족 5 × 성별 2
3. 초상화 5장: `face_A_2` ~ `face_E_2` (64×64 평소 표정). 이후 3 기쁨 / 5 당황 / 7 분노 / 10 지침
4. 1층 평면도 배경 `floor1.png`, `floor1_night.png` (384×216)
5. UI 아이콘 시트 `icons.png` (16×16: 동전/평판/소문/향유병/결/시계/피로/하트/횃불/재료/업적)
6. (2차) 심연구 입구 배경 1장, 재료 아이콘 7종, 제작품 아이콘 7종 — 규격은 ASSET_SPEC에 추가 예정

### 5-2. UX 제안서 1차분
마크다운 1장 + 목업 이미지(PNG, 해상도 자유). 내용:
1. 데스크톱 레이아웃 안 (상단바·캔버스·로그·패널 배치, 패널 폭, 탭 순서)
2. 관계 탭 카드 디자인 (초상화 + 관계 바 + 버튼 3개를 어떻게 놓을지)
3. 모달 디자인 (스토리 이벤트 선택지, 대화 흐름). 초상화 자리 포함
4. 모바일 세로 레이아웃 안
5. 색 팔레트 (현재: 배경 #1b1a22, 패널 #26242f, 강조 #d9a35b, 좋음 #7fcf8a, 나쁨 #e06c6c) 와 픽셀 폰트 추천
6. 구현 난이도를 모르니 "꼭" / "있으면 좋음" 으로 나눠 적는다

### 5-3. 산출물 형식
- 이미지: PNG, 투명 배경(배경 이미지 제외), 규격 픽셀 그대로(업스케일 금지). 파일명은 ASSET_SPEC과 일치
- UX: 마크다운 + PNG 목업. 코드·CSS는 쓰지 않아도 된다

## 6. 작업 규칙

- 파일명에 한글·공백을 쓰지 않는다 (GitHub Pages 주소가 깨진다)
- 인물 코드 A~E 는 고정이다. 이미지·데이터 전부 이 코드로 잇는다
- 모르는 건 묻기보다 합리적 기본값으로 정하고 "이렇게 잡았다"고 적는다
- 대사·설정·수치에 대한 의견이 있으면 "Claude에게 메모" 항목으로 따로 적는다. 직접 쓰지 않는다

## 7. 폴더 지도

```
index.html, style.css   진입점·스타일 (UX 구현 대상)
src/data/               게임 데이터 (Claude 관리)
src/                    엔진 (Claude 관리)
assets/manifest.js      에셋 경로 목록. 파일이 없으면 색 블록으로 대체
assets/sprites|bg|ui    ← GPT 이미지가 들어갈 자리
assets/ref/             인물 외형 참고 그림 5장 + 식별 요소 메모 (참고 전용)
docs/ASSET_SPEC.md      이미지 규격·파일명·좌표
docs/LORE.md            세계·인물 설정 (외형 기준)
docs/GAME_DESIGN.md     시스템 기획 (UX 제안 시 참고)
```
