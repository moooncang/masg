# 실제 게임 UI 적용 · 2026-10-13

사용자의 “UX, UI 디자인 개편, 실적용” 요청에 따라 Codex가 실행 코드를 적용했다. 이전의 Claude 구현 대기 상태를 대체한다. 승인된 v3 화면과 생산 에셋을 기준으로 하며, 아래 이미지는 HTML 시안이 아니라 실행 중인 게임을 Chromium에서 캡처한 것이다.

향유 구매/조향, 관계·대화·선물·출장·영입 조건, 일일 장부·계약·소식, 저장·마감·새 게임도 같은 창 구조로 연결했다. 신규 게임 시스템이나 수치·대사·저장 스키마 변경은 포함하지 않는다.

## 코드 연결

- `index.html`, `style.css`: 현장 중심 레이아웃, 관리 창, 모달, 반응형, 로컬 Galmuri 폰트.
- `assets/manifest.js`: 실제 게임에서 HD 에셋을 로드하도록 변경. Native 호환 파일도 보존.
- `src/render.js`: 논리 좌표 384×216, backing canvas 1536×864. 64×96 소스 프레임을 직접 샘플링하며 image smoothing을 끈다. 배경은 1672×941 원본, 초상화는 128×128이다. 영입 후 C/D/E는 직원 의상 에셋을 사용한다.
- `src/ui.js`: 8개 메뉴, 게임 창, 선택 상태, 실시간 DOM 갱신, 기존 `Sim` API 연결. 갱신 시 포커스·스크롤·입력값을 보존한다. 대화는 배경을 inert로 두고 포커스를 가두며, 큐와 내용 교체가 끝나면 원래 0/1/2/4배속을 복원한다.
- `src/sim.js`, `src/state.js`, `src/data/*`: 이번 작업에서 변경하지 않았다. `masg_save_v1` 저장과 기존 마이그레이션을 그대로 사용한다.

미확장 베드는 어둡게 표시하고 확장으로 연결한다. 현장 인물은 대기 프레임을 사용하고 시술 중에만 작은 상하 움직임을 준다. 별도의 이동 경로/시술 애니메이션 시스템은 추가하지 않았다. 모바일 현장은 축소 대신 좌우로 이동하며, 관리 창 내부 내용은 세로 스크롤한다.

## 검증 및 재실행

`tests/ui-smoke.cjs`는 매번 격리된 브라우저 컨텍스트를 사용하므로 기존 사용자의 저장을 건드리지 않는다.

```bash
# 저장소 루트, 첫 터미널
python3 -m http.server 8123

# 둘째 터미널 — Playwright가 없는 환경에서만 설치
npm install --no-save --package-lock=false playwright

# 시스템 Chromium 경로는 환경에 맞게 변경 가능
CHROMIUM_PATH=/usr/bin/chromium node tests/ui-smoke.cjs
```

`BASE_URL`로 서버 주소, `UI_SCREENSHOTS`로 캡처 디렉터리를 지정할 수 있다. 기본 캡처 위치는 `/tmp/masg-ui-qa`다. 테스트 의존성은 게임 실행에는 필요하지 않다.

확인한 항목:

- 8개 메뉴와 HD 이미지 로딩, 360/390/768/1360px 화면 및 관리 창 가로 넘침 없음.
- 수건의 대상 직원 적용과 대상 삭제 경합, 업무 변경, 고용과 정원 제한.
- 베드 2→8 확장과 잠금 해제, 제작 재료 차감·수건 2개 생산·설비 중복 제작 방지.
- 탐사 피로 69/70 경계, 3명 제한, 잠긴 층·늦은 귀환·선택 후 조건 변경, 실제 출발과 귀환.
- 숨겨진 업적 제목·본문 비노출, 영입 조건 및 이미 진행한 일회성 제안 상태.
- 주기적 갱신 후 입력·포커스·스크롤 유지, 모달 큐·교체 후 배속 복원, Tab 순환·Escape 취소.
- 저장 성공·저장소 실패 안내·기존 스키마 재접속, 낮/밤 배경과 실제 시술 손님 렌더링.

GitHub Pages 배포는 기존 `.github/workflows/pages.yml`의 대상 브랜치 push 동작을 그대로 사용한다.
