## 3. 화면 전체의 공통 기준

### 승인된 인상 유지

따뜻한 등불, 낡은 목재, 황동 모서리, 짙은 보라 그림자, 손으로 그린 도트 아이템을 공유한다. UI만 매끈한 웹 스타일로 바뀌면 안 된다. 화폐·시계·아이템·버튼·선택 표시·스크롤 손잡이·글자도 같은 밀도로 제작한다.

플레이 HUD의 **게임 제목, 한자 로고, 영문 부제는 계속 제거**한다. 가게 이름은 설정과 저장 데이터에서만 관리한다. 고정 오른쪽 대시보드를 복원하지 않는다.

원본 1px 정렬, 최근접 정수 배율, 2px 계단 모서리, 1px 밝은 안쪽 선, 평평한 내용 바탕이 기본이다. 버튼은 기본/포커스/누름/비활성 4상태, 아이템 슬롯은 기본/선택/없음/잠김 4상태를 공유한다. 누름은 내용 1px 이동과 안쪽 그림자로 표현한다.

팔레트는 외곽선 `#211c29`, 그림자 `#382a32`, 목재 `#704b3b`, 밝은 목재 `#a57950`, 황동 `#d7ac62`, 글자 `#eee1bc`, 긍정 `#91ad74`, 손실 `#c97868`를 기준으로 한다. 문장 뒤에 복잡한 나뭇결을 깔지 않는다. 상태는 색+이름/아이콘으로 전달한다. 한글 픽셀 글꼴은 Galmuri11 후보이며 라이선스·글리프 확인 후 배포한다.

### 공통 창

일반 관리 창은 하나만 열고 기존 게임은 현재 속도로 진행한다. 다른 메뉴를 누르면 창 내용을 바꾼다. **필터·선택·스크롤·키보드 포커스는 1초 갱신에 초기화하지 않는다.** 값만 갱신하며 선택 대상이 실제로 사라졌을 때만 안내하고 대체한다.

스토리·대화·마감·파괴적 확인은 별도 모달 계층이다. 읽는 동안 정지하고 큐 마지막에서 원래 속도를 복구한다. 원래 0이면 0으로 돌아가야 한다. 이 부분의 현재 결함은 검토 문서에 기록했다.

닫기는 항상 오른쪽 위. ESC는 닫기 가능한 창만 닫는다. 의무 선택 스토리를 ESC나 배경 클릭으로 넘기지 않는다. 하단 행동 영역을 고정하고 긴 내용은 본문만 스크롤한다. 그림에 버튼 글자를 굽지 말고 실제 버튼과 접근성 이름을 둔다.

## 4. 플레이 HUD·현장

### 구성

상단 왼쪽: 금/은/동화 3종, 평판 단계·수치, 소문. 오른쪽: 날짜·시간대·시각, 정지/1×/2×/4×. 화폐는 각인·실루엣·색을 다르게 그린 16×16 아이템으로 표시하며 계산은 실제 동화 잔액에서 한다. 부채는 전체 금액에 부호 하나를 붙여 표현하고 동전마다 음수를 나누지 않는다.

하단 중앙의 **8개 메뉴 순서 고정**: 가게(장부) / 직원(얼굴) / 확장(망치) / 향유(병) / 탐사(횃불) / 관계(편지) / 업적(훈장) / 설정(톱니). ‘던전’ 기능의 화면 이름은 ‘탐사’로 제안하며 내부 `dungeon` 키는 유지한다.

왼쪽 작은 직원 띠는 최대 3명과 현재/정원. 12명 이상을 모두 펼치지 않는다. 나머지는 직원 창으로 연결한다. 피로는 피로 막대임을 툴팁·이름으로 명시하고 탐사/출장은 상태 아이콘으로 구별한다.

오른쪽 탐사 칩은 **`s.expedition`이 있을 때만** 귀환 시각·참가자·진행을 표시한다. 진행 중 새 파티 출발 버튼은 없다. 클릭하면 현재 탐사 창을 연다. 귀환하면 칩을 제거하고 짧은 결과 알림과 가방/직원 바로가기를 보여 준다. 강제로 매번 모달을 열지 않는다.

시술·업적 알림은 동일한 알림 레인에서 순서대로 표시한다. 업적은 현재 2.6초 노출을 기본으로 큐 처리하고 내역은 장부에 남긴다. 도구띠나 확정 버튼을 덮지 않는다.

### 8베드와 픽셀 좌표

세계는 384×216 유지. 베드 칸은 x=`140,200,260,320`, y=`8,80`, 각 56×64. 위 1~4, 아래 5~8. 실제 베드는 각 칸 `(x+10,y+36,36,14)`, 직원 `(x+36,y+8)`, 진행 바 `y+h−8`, 높이 4px다. 접수·대기·조향·계단 좌표는 최신 `ASSET_SPEC.md` 그대로다.

미개설은 인덱스가 `s.rooms.length` 이상인 칸만 마스킹한다. ‘베드 3·4는 잠기고 5·6은 개설’ 같은 비연속 상태를 그리지 않는다. 완전 개설 예시 화면에는 8개 모두 밝게 표시한다. 그림 속 인물은 런타임 엔티티로 분리하고 배경에 넣지 않는다.

기본 논리 표면은 위 HUD 20 + 세계 216 + 아래 띠 28 = **384×264** 제안이다. 일반 창은 최대 약 344×194 논리 px로 세계 위에 뜬다. 승인 이미지의 16:9는 아트 표현이며 구현 좌표는 이 명세가 우선한다. 정수 배율 확대 후 여백을 짙은 배경으로 채운다. 새 아트를 위해 세계 좌표나 시뮬레이션을 바꾸지 않는다.

## 5. 가게·향유·설정

가게는 작은 장부 창의 내부 책갈피 **오늘 / 메뉴 / 기록**으로 정리한다. 오늘에는 수입·지출·시술·이탈, 사용 중/개설 베드, 대기/좌석, 단골, 직원/정원, 탐사·출장, 전속 계약·기사단 지정·오늘 이벤트를 담는다. 메뉴는 현행 4종과 잠금·대금·시간·향유·예약 표시를 보존한다. 기록에는 7일 장부와 전체 로그를 둔다. 미달성 공개 업적 중 진행 상위 4개를 장부 가장자리 바로가기로 둔다.

향유 창은 승인된 병 슬롯을 유지한다. 진정·온열 1/5병 구매, 월하향 상태, 레이나 조향 배치·생산을 표시한다. **가격은 `Sim.oilPrice()` 결과**를 사용한다. 카샤 영입·관계/계약·기간 할인 등이 중첩되므로 v2의 고정 숫자를 넣지 않는다. 월하향에는 상단 구매 버튼을 만들지 않고, 해금 후 제작 레시피와 조향 조건으로 연결한다. 조향은 일일 처리이므로 존재하지 않는 실시간 제조 타이머를 표시하지 않는다.

설정은 이름 / 저장 / 마감 / 통계 / 새 게임을 나누고 새 게임을 별도 위험 영역에 둔다. 마감 시 시술·출장·탐사를 현재 코드가 마무리하므로 확인창에서 그 영향을 설명한다. 저장 성공은 `State.save()` 결과로 판단하며 단순 클릭만으로 성공 문구를 표시하지 않는다.

## 6. 직원·구인

직원 창은 왼쪽 얼굴 목록, 오른쪽 선택 직원 상세. 목록 상단에 `사장 포함 N/M`. 본문에는 현재 역할·배치·활동, 능력 4개, 특성, 피로, 경험, 배치 버튼, 온열 수건 사용을 둔다. 경험 분모는 **`level × CONFIG.XP_PER_LEVEL`**이며 Lv.3은 300이다. 모든 레벨을 100으로 고정하지 않는다.

| 인물 | 실제 가능한 배치 |
|---|---|
| 사장·네르·일반 직원 | 시술 / 휴식 |
| 레이나 | 접수 / 조향 / 시술 / 휴식 |
| 영입 세르피나·이브레아 | 시술 / 휴식 |
| 영입 카샤 | 접수 / 시술 / 휴식 |

배치는 `Sim.postsFor()`로 생성한다. 시술·출장·탐사 중 변경 불가 사유를 표시한다. 탐사 중을 시술 중으로 표시하지 않는다. 직원 목록에는 일반 직원도 전원 있어야 한다.

온열 수건은 **대상을 선택한 뒤** `현재 피로 → max(0,피로−40)`와 보유 수량을 보여 준다. 선택 대상 ID를 전달해 사장에게 잘못 사용되는 기본 동작을 막는다. 실제 잔여 수량을 재검증한다. 직원 원격 사용 가능 여부 등 기존 정책을 UI에서 임의로 바꾸지 않는다.

구인 내부 탭에는 기본 3명, 게시판 구매 후 5명. 능력·특성·고용비·할인 반영 일당을 비교하고 돈 부족과 정원 부족을 구분한다. 정원 가득이면 숙소 계열 확장 링크를 제공한다. 해고는 일반 고용 직원에게만, 업무 중에는 불가. 사장·엘리트에게 해고 버튼을 붙이지 않는다.

정원 확장은 일반적으로 5→7→9→12이나, **엘리트 영입 시 인원에 맞춰 정원이 보정되는 예외**가 있다. 12를 하드코딩 상한으로 쓰지 않는다.

## 7. 확장 20종

긴 구매 카드 대신 왼쪽 분류→가운데 작은 단계 도면→오른쪽 선택 확장 상세다.

| 분류 | 기존 ID |
|---|---|
| 베드 | `room3, room4, room5, room6, room7, room8` |
| 대기 | `seats1, seats2, tea` |
| 운영 | `sign, shelf, board, soundproof, backdoor, book, still, lantern` |
| 숙소 | `dorm, floor2, annex` |

각 항목에 이름·효과·선행 조건·평판·실제 금액·개설/잠금/자금 부족/완료를 표시한다. 둘 이상의 부족 조건을 함께 보여 준다. 구매는 즉시 완료이며 새 건설 타이머를 추가하지 않는다. ‘2층 리모델링’은 현재 직원 정원과 회복 효과이지 새 층 맵 전환이 아니다.

베드 4 예시: 베드 3+평판 단골 가게, 15,000동. 잔액 12,430동이면 부족액 2,570동. 화폐 그림은 금2/은5/동70으로 표현한다. 다음 베드 순서는 실제 `requires`를 읽는다.

## 8. 탐사 / 가방 / 제작

기존 던전 탭의 네 덩어리를 하나의 게임 창 안에서 **탐사 / 가방 / 제작**으로 분리한다. 진입은 횃불, 조향실·아이템 바로가기는 해당 내부 탭을 지정해서 연다. 화면 이동 후 돌아가도 선택한 깊이·직원·레시피를 유지하되 무효 상태는 정리한다.

### 탐사 편성

왼쪽은 3개 깊이 노드 지도, 오른쪽은 선택 층→파티 3슬롯→귀환·영업 영향→출발이다. 전투력·장비 전투 슬롯·입장료·체력 바를 새로 만들지 않는다.

| 깊이 | 시간 | 평판 | 직원 최소 레벨 | 기본 피로 | 기본 결 확률 | 가장 늦은 출발 |
|---|---:|---|---:|---:|---:|---|
| 1 입구 동굴 | 2시간 | 무명 | 1 | +30 | 0% | 21:30 |
| 2 마력 수맥 | 4시간 | 입소문 | 3 | +50 | 15% | 19:30 |
| 3 심연 정원 | 6시간 | 단골 가게 | 5 | +70 | 35% | 17:30 |

귀환이 **23:30 이하**일 때 가능하다. 브리프의 ‘오전에 보내야 당일 귀환’은 요약이며 실제 마감 기준을 적용한다. 경계 시각은 허용, 1분 뒤는 불가다.

선발은 사장 제외, 유휴 상태, 피로 **70 미만**, 조향 배치 제외, 선택 층 최소 레벨, 1~3명이다. `Sim.canExpedition()`을 최종 판정으로 사용한다. 제외 직원은 접힌 ‘참가 불가’ 목록에서 이유를 볼 수 있다. 출발 전 선택을 다시 검사하고, 층 변경으로 레벨이 부족해지면 해당 슬롯을 해제하며 이유를 알린다.

접수 담당을 보내면 ‘접수 공백’을 표시하되 새로운 출발 금지 조건으로 만들지 않는다. 예상 피로는 직원의 특성과 상한을 반영하고, 기본 확률을 성공 보장처럼 표현하지 않는다. 세르피나의 결 면역·이브레아의 희귀 보정도 설명할 수 있어야 한다. 지도에 표시하는 재료는 해당 층 전리품 표를 그대로 읽으며 확정 수량을 약속하지 않는다.

탐사 중은 같은 창을 진행 화면으로 전환한다. 현재 파티·층·귀환 시각·남은 시간만 표시하며 기존에 없는 취소/가속/추가 파티 버튼은 넣지 않는다. 귀환 후 획득물은 가방, 피로는 직원 상세로 연결한다. ‘결’은 현재 코드에서 피로 100 처리이며 별도 직원 시술 퀘스트가 실제로 생성되는 것으로 표현하지 않는다.

### 가방

재료 7종을 이름·도트 아이콘·수량으로 표시한다. 0개도 선택 가능하게 남겨 용도와 확보 층을 확인한다. 오른쪽 상세에는 설명, 사용하는 레시피, 1개 판매 가격, 판매 버튼을 둔다. ‘모두 팔기’ 기본 버튼은 넣지 않는다. 현재 판매 1개 흐름을 유지하고, 제작에 사용할 재료임을 표시한다.

소모품 4종은 별도 필터다. 온열 수건→직원 선택, 향초→당일 인내 배율, 부적→당일 점수, 강장제→사장 피로 회복. 오늘 효과는 일일 초기화됨을 표시한다. 중첩·반복 사용 규칙을 임의로 바꾸지 않는다. 설비 3종은 ‘설치됨’ 도감으로 보여 주고 소모품 사용 버튼을 붙이지 않는다.

### 제작 10종

레시피 목록→결과 아이콘·개수→재료 보유/필요→잠금·영구 상태→제작 순서다. 필터는 전체 / 향유 / 소모품 / 설비. 가능한 항목 필터는 선택 사항이며 기본 목록에서 잠금 레시피를 삭제하지 않는다.

| 결과 | 재료 | 수량·조건 |
|---|---|---|
| 진정 향유 | 진정초 2 | 1병 |
| 온열 향유 | 진정초 1, 온천수 1, 마력 결정 1 | 1병 |
| 월하향 | 월하 꽃 1, 마력 결정 2 | 1병, 증류기+월하향 해금 |
| 온열 수건 | 온천수 2 | **2개** |
| 진정 향초 | 진정초 3, 온천수 1 | 1개 |
| 마력 부적 | 마력 결정 3, 마력핵 파편 1 | 1개 |
| 거미줄 시트 | 동굴 거미줄 4 | 영구 설비, 1회 |
| 용린 베드 보강 | 용린 조각 3, 동굴 거미줄 2 | 영구 설비, 1회 |
| 마력 등불 | 마력 결정 5, 마력핵 파편 1 | 영구 설비, 1회 |
| 회복 강장제 | 진정초 2, 마력 결정 1 | 1개 |

제작은 즉시 재료 차감과 결과 지급이다. 돈·대기열·제조 시간·조향 직원 필수 같은 새로운 조건을 추가하지 않는다. 현재 `canCraft()`는 영업 종료도 막지 않는다. 성공 후 변경된 재고를 갱신하고 선택 레시피는 유지한다.

## 9. 관계·영입

5인 선택띠+한 명의 상세를 유지한다. 미만남 인물은 이름/초상화 숨김, 실제 해금 조건만 표시. 만난 인물은 관계 값·단계, 하루 대화 상태, 선물·출장, 훅·진행을 표시한다.

| 인물 | 이야기 영입 조건 | 영입 후 |
|---|---|---|
| C 세르피나 | 관계≥75 + `a_knights`(기사단 방문 20) + `C_designated` | 시술/휴식, 기사단 체력 |
| D 이브레아 | 관계≥75 + `a_core`(마력핵 파편 획득) + `D_quest_done` | 시술/휴식, 측정구 |
| E 카샤 | 관계≥75 + `a_oil50`(상단 구매 50병) | 접수/시술/휴식, 상단주 |

조건표는 실제 세 조건을 각각 체크한다. 제작한 향유는 상단 구매 50병에 포함하지 않는다. 숨긴 업적은 달성 전 업적첩에서 이름·보상·진행을 노출하지 않는다. D의 기존 훅에는 파편 이름이 이미 안내되어 있으므로 관계 안내와 업적첩의 숨김 정책을 섞지 않는다.

‘즉시 영입’ 버튼을 새로 만들지 않는다. 조건 달성은 기존 이야기 이벤트가 제안하며 선택 결과로 영입한다. 영입 후 얼굴 옆 배지를 직원으로 바꾸고 새 직함과 레벨·배치를 표시한다. **출장은 제거**, 대화·선물은 유지하되 업무 중 대화 불가를 반영한다. 현장에서도 이후 직원으로 나타날 수 있다. 옛 ‘C/D/E는 항상 손님’ 규칙은 폐기한다.

영입 이벤트는 현재 `once:true`라 거절하면 같은 제안이 재등장하지 않는다. 조건 화면에 상태를 구분하고 선택 전 일회성임을 UI 설명으로 알린다. 원문 대사와 선택지 문장은 변경하지 않는다. 영입은 정원 가득이어도 코드가 정원을 보정하므로 일반 고용처럼 막지 않는다.

## 10. 업적 76개

훈장첩은 전체 필터+6분류 책갈피, 목록, 선택 업적 상세로 구성한다. 실제 분류 개수는 **가게21 / 평판13 / 확장12 / 향유6 / 던전10 / 관계14**다. 진행/완료/영입 조건 필터를 제공할 수 있으나 필터 때문에 전체 76의 분모가 바뀌지 않게 한다.

각 공개 업적에 도트 훈장, 이름, 실제 목표 수치, 막대, 보상, 영입 조건 태그. 복수 지표는 개별 조건을 보여 주며 종합 진척은 현행 최소 비율을 따른다. 완료는 달성 일자. 숨김 미달성은 물음표만 보여 주며 툴팁·접근성 이름에도 비밀을 노출하지 않는다.

보상은 `checkAchievements()`가 즉시 지급한다. **수령 버튼·빨간 미수령 배지 없음.** 완료 알림은 장부로 다시 볼 수 있고, 영입 조건 태그를 누르면 관련 인물 조건으로 이동한다. 단골 30명 업적과 현 상한 20의 충돌은 검토 문서에 따로 기록했다. 화면에서 숫자를 몰래 바꾸지 않는다.

## 11. 모바일

모바일은 긴 세로 웹 페이지 대신 상단 HUD, 작은 현장, 활성 게임 창, 하단 도구띠를 유지한다. **8개 메뉴를 2행×4칸**으로 표시해 44px 터치 영역과 한글 이름을 확보한다. 설정·업적을 더보기 속으로 숨기지 않는다. 가로 화면은 1행을 사용할 수 있다.

제작 화면은 목록→선택 상세의 두 단계로 전환하고 뒤로 가면 필터·스크롤을 복원한다. 직원은 직원 선택→상세, 탐사는 깊이→파티→출발 요약, 업적은 분류→목록→상세로 동일한 규칙을 사용한다. 출발·제작·닫기는 하단 안전 영역에 가리지 않는다.

360/390px에서는 세계 원본 384px를 흐리게 축소하지 않는다. 작은 현장은 별도 축약 지도 표현 또는 내부 이동 영역을 사용하고, 세계 원본 크기·좌표는 유지한다. 2×4 메뉴와 창은 가로 넘침 없이 뷰포트 폭에 맞춘다. 키보드 탐색·포커스·스크린리더 레이블은 도트 연출과 별개로 제공한다.

## 12. 아트 제작 범위와 우선순위

기존 워킹64×24·초상화64×64·배경384×216 규격 유지. 새 배경은 8칸 기준으로 재제작한다. 한 프레임에 근접 인물이 많아지므로 가구 대비를 낮추고 진행 바 영역을 비워 둔다. 접수 최대 2명과 계단의 시술 대기/휴식 줄도 남겨 둔다.

추가 UI 생산 후보: 화폐3, 메뉴8(횃불·훈장 포함), 재료7, 제작 결과10(향유3+소모품4+설비3), 상태 아이콘(탐사/출장/피로/잠금/장착), 창·버튼·슬롯·스크롤·툴팁 공통 스킨. **브리프는 아이콘 11종을 말하지만 ASSET_SPEC의 시트 본문은 아직 8종**이므로 manifest 연결을 먼저 확정한다. 기존 인덱스를 바꾸지 말고 추가 atlas 또는 개별 파일로 확장한다.

꼭: 승인된 화풍, 8베드·8메뉴, 신규 기능 진입점, 상태별 정확한 버튼, 기존 조건·금액·저장 보존, 모바일·키보드 동작.

있으면 좋음: 현장 클릭 연결, 업적·레시피 필터, 미세한 픽셀 상태 전환, 귀환 획득물의 슬롯 이동 연출. 전투·제작 대기열·자동 영입·새 성장 수치는 이번 UI 개편에서 추가하지 않는다.

개별 네이티브 에셋과 엔진 적용은 아직 완료되지 않았다. Claude에게는 이 명세와 [기능 연결표](IMPLEMENTATION_HANDOFF.md)를 함께 전달한다.
