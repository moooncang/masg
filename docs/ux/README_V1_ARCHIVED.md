> 사용자 피드백으로 아래 시각 방향은 폐기했다. 현재 구현 기준은 [v2 문서](README.md)와 `previews/v2/`다. 제목·한자·고정 대시보드·웹 카드 배치를 따라 구현하지 않는다. 아래는 변경 이력이다.

기준: `d1f03e0` / 2026-10-13. 담당 범위는 `docs/GPT_BRIEF.md`의 최신 역할 분담을 따른다. **게임 엔진·대사·밸런스 변경 없이, 화면 설계와 새로 그린 아트 방향을 전달한다.** 이전 `docs/design/`의 확장 기획은 이번 화면에 구현된 것으로 취급하지 않는다.

## 2. 디자인 방향

플레이 중 중심은 가게에서 움직이는 사람이다. 넓은 현장 옆에 짧은 운영 패널을 둔다. 나무 질감과 픽셀 장식은 현장·초상화에 집중하고, 숫자·본문·버튼은 읽기 쉬운 평면 UI로 만든다.

첫 시선은 시술실과 대기실, 두 번째는 재고·피로처럼 조치가 필요한 상태, 세 번째는 성장과 관계로 이동한다. 정보가 많아져도 속도 조절과 현재 탭은 이동하지 않는다. 새 기능을 더하기보다 이미 있는 기능을 찾기 쉽도록 정리한다.

## 3. 데스크톱 구조

권장 기준은 1360×900 이상이다. 상단 HUD 높이 96px, 좌우 여백 32px, 현장과 패널 사이 28px, 패널 폭 432px(내부 여백 20px). 오른쪽 패널 안에서 여섯 탭을 고정 순서로 배치한다: **가게 / 직원 / 확장 / 향유 / 관계 / 설정**.

- 상단: 가게 이름, 날짜·시각·영업 여부, 소지금, 평판 단계·수치, 소문, `일시정지 / 1× / 2× / 4×`. 금액은 현행 화폐 변환 함수를 사용한다. 별도 예산 계산 규칙을 만들지 않는다.
- 현장: 384×216 캔버스를 2배인 768×432로 표시하고 여유 공간은 레터박스로 남긴다. 3배는 가용 폭 1152px와 높이 648px가 확보될 때만 허용한다. CSS로 캔버스를 가변 비율 확대하지 않는다.
- 현장 하단: 향유 현황 및 향유 탭 이동, 최근 기록. 기록에는 시각과 유형을 함께 표시한다. 계속 갱신되는 로그가 패널을 밀어내지 않게 높이를 제한한다.
- 운영 패널: 탭과 제목은 유지하고 내용 영역만 스크롤한다. 탭별 스크롤 위치를 기억한다. 탭 이동으로 시뮬레이션 속도를 변경하지 않는다.
- 1100~1279px: 패널 360px, 현장 1배 또는 2배 중 가용 공간에 맞는 정수 배율. 1100px 미만은 세로 배치로 전환한다. 두 열을 억지로 유지해 현장을 잘라내지 않는다.

목업의 고해상도 실내 그림과 방 상태표는 시각적 배치 예시다. 최종 배경의 방 좌표나 스프라이트 충돌 좌표로 사용하면 안 된다. 실제 캔버스에서는 `ASSET_SPEC.md` 좌표가 우선한다.

### 상태와 조작

시술 중 / 빈 방 / 미개설을 텍스트로 구분하고, 진행률은 같은 하단 위치에 둔다. 대기 인원과 수용량은 실제 엔진 값으로 표시한다. 원근감 있는 가구가 이동 경로와 진행 바를 가리지 않게 한다.

직원 빠른 배치는 기존 직원 탭의 배치 조작으로 연결한다. 직원 이름, 현재 배치, 피로, 변경 버튼을 한 줄에 둔다. 시술 중이면 버튼 옆에 사유를 남긴다. 피로 경고 기준은 기존 엔진 값을 재사용하며 UX에서 별도 임계치를 만들지 않는다.

## 4. 기존 기능의 위치와 표시 규칙

| 탭 | 필수 내용 | UI 처리 |
|---|---|---|
| 가게 | 오늘 수입·지출·시술·이탈, 시술실·대기실, 단골 수 | 상단 2×2 수치 카드 → 직원 빠른 배치 → 운영 현황 |
| 가게 | 메뉴 4종, 다음 목표 4개, 장부 7일 | 명확한 섹션 버튼으로 펼침. 열면 실제 상세·조작 전부 유지. 장부는 날짜/수입/지출/순액 순서 |
| 직원 | 능력치 4, 특성, 피로·경험, 현재 배치 | 이름 → 역할 → 능력치 → 특성 → 두 막대 → 배치 선택. 막대에 수치와 단위 병기 |
| 직원 | 접수/조향/시술/휴식, 구인 3명, 고용·해고 | 배치는 2×2 버튼. 지원자는 별도 구인 섹션에 3명 표시. 해고는 관리 메뉴에 분리하고 대상·영향 확인 |
| 확장 | 업그레이드 14종, 비용, 효과, 잠금·구매 | 구매 가능/조건 부족/완료 구분. 숨기지 말고 잠금 사유 표시. 구매 후 동일 카드에서 완료 상태로 전환 |
| 향유 | 진정·온열 1병/5병 구매, 월하향 해금, 조향실 | 재고 → 용도 → 구매 수량별 실제 가격. 잠긴 월하향은 조건만 표시. 조향 담당·생산 상태를 하단에 고정 |
| 관계 | 직원 2명, 손님 3명, 관계 값·단계·설명·훅 | 다음 절의 카드. 긴 소개·훅은 ‘인물 정보’ 펼침. 퀘스트 진행도가 있으면 카드에 표시 |
| 설정 | 가게 이름, 저장, 오늘 마감, 새 게임, 누적 통계 | 일반 설정/진행 관리/새 게임을 분리. 저장 완료 피드백. 새 게임에는 저장 초기화 대상 명시 |

펼침 섹션에 마지막 상태를 기억한다. 구매 실패 시 버튼만 무반응으로 두지 말고 부족 금액 또는 조건을 가까이 표시한다. 탭 알림은 실제 즉시 행동 가능한 항목만 센다. 수치 자체가 높다는 이유로 경고하지 않는다.

## 5. 관계 카드

최종 초상화는 64×64 원본을 1배로 표시한다. 카드 상단은 `초상화 | 이름·역할·오늘 상태 | 관계 수치`의 세 부분이다. 아래에 관계 막대, 단계명, 소개와 훅, 행동 버튼을 놓는다. 목업의 세로 초상화는 컨셉 시트 크롭 표시이며 최종 규격을 뜻하지 않는다.

직원 A·B에는 **대화 / 선물**, 손님 C·D·E에는 **대화 / 선물 / 출장**을 배치한다. 최신 브리프의 ‘버튼 3개’ 요구를 확인했지만, 현재 `UI.personCard()`와 `Sim.canOutcall()`에서 직원은 출장 대상이 아니다. 직원에게 가짜 출장 버튼을 추가하지 않는다.

| 상태 | 표현 | 행동 |
|---|---|---|
| 오늘 대화 가능 | 초록 점 + ‘대화 가능’, 강조 버튼 | `Sim.canTalk()` 결과 사용 |
| 오늘 횟수 사용 | ‘오늘 대화함’ | 버튼 비활성. 내일 다시 가능하다는 안내 |
| 직원 시술·출장 중 | 현재 업무명 | 대화 불가 사유 표시. 선물 가능 여부는 별도 판정 |
| 영업 종료 | ‘영업 종료’ | 현재 엔진처럼 대화·선물·출장 비활성 |
| 만나지 못한 손님 | ‘???’, 실루엣 자리, 실제 해금 조건 | 초상화·소개·이름 선공개하지 않음 |
| 선물 재고 없음 | ‘선물할 향유 없음’ | 향유 관리로 이동 가능. 재고가 없는 선택지는 제외 |
| 출장 불가 | 실제 막힌 조건 표시 | 관계/시각/사장 업무/당일 이용 여부 등을 현행 판정으로 설명 |

‘오늘 대화 가능 N명’은 친밀도나 해금 수가 아니라 현재 `canTalk` 결과를 합산한다. 카드 순서는 직원 A·B, 손님 C·D·E로 유지한다. 가능 상태가 바뀔 때 카드가 갑자기 재정렬되지 않게 한다. ‘대화 가능만’ 필터는 선택 사항이다.

관계는 `낯섦 / 안면 / 신뢰 / 각별`의 실제 단계명과 0~100 수치를 표시한다. 예시 목업의 축약 표현은 구현 시 이 단계명을 보완한다. 각 단계 기준은 기존 데이터에서 가져온다.

## 6. 대화·이벤트 모달

데스크톱 대화 폭 720px, 바깥 여백 최소 24px. 최종 64×64 초상화는 2배 128×128로, 본문은 16px·행간 1.8로 표시한다. 내용이 길면 본문만 스크롤하며 선택지와 확인 버튼을 화면 밖으로 밀어내지 않는다.

대화 흐름은 현행 엔진과 동일한 **인사 → 주제 선택 → 답변 선택 → 반응 → 확인**이다. 목업 대사는 원본 `A_ledger`이다.

- 주제 선택만으로 하루 대화 횟수를 소모하지 않는다. 현재 `Sim.talk()` 호출인 답변 선택 시점에 소모됨을 안내한다.
- 선택지 2~3개는 동일한 시각적 비중으로 세로 배치한다. ‘정답’처럼 보이는 기본 강조를 피한다. 버튼 번호는 순서 표기이며 단축키 구현을 뜻하지 않는다.
- 결과는 기존 원문을 그대로 보여 준다. 선택 전 호감 증감을 새로 노출하지 않는다.
- 주제 선택 단계의 ‘나중에’, 선택 전 닫기, 선택 후 ‘확인’을 구분한다. 일회성 스토리의 중간 닫기·취소 가능 여부는 기존 이벤트 생명주기를 따른다.
- 하루 이벤트는 본문 + 확인, 스토리 이벤트는 본문 + 조건부 선택지 2~3개, 마감 정산은 수입/지출/결산/시술/이탈 + 다음 날 진행의 동일한 틀을 사용한다. 누적 통계를 정산 수치와 섞지 않는다.
- 열릴 때 포커스를 제목 또는 본문 시작으로 옮기고 모달 안에 가둔다. 닫힌 뒤 원래 버튼으로 돌린다. ESC·배경 클릭은 취소 가능한 단계에서만 작동한다. 확정 선택에 이중 입력이 들어오지 않게 한다.
- 모달 중 시뮬레이션 정지와 복귀는 기존 모달 처리 방식부터 확인한다. UX 제안은 ‘읽는 동안 진행 정지, 닫을 때 이전 속도 복원’이며, 이미 사용자가 일시정지한 상태를 임의로 1배속으로 바꾸면 안 된다. 새 게임 규칙으로 몰래 바꾸지 않는다.

## 7. 모바일 세로

390px 목업은 1배 384×216 현장을 담을 수 있도록 현장 좌우 여백만 3px로 줄였다. 상단은 가게·시간 행과 금액·속도 행으로 나누고 스크롤 중에도 속도를 유지한다. 평판·소문은 보조 상태줄 또는 펼침 정보로 접근 가능해야 한다. 현장 밑에 재고, 여섯 탭, 선택한 패널을 순서대로 배치한다.

- 384px보다 좁은 뷰포트에서는 캔버스를 흐리게 축소하지 않는다. 현장만 가로 스크롤 가능한 384px 영역으로 두고 양쪽에 이동 단서를 표시한다. 문서 전체의 가로 넘침은 금지한다.
- 관계 카드는 한 열. 초상화 64×64, 버튼 최소 44px 높이, 세 버튼이 한 줄에 들어가지 않으면 대화를 한 행, 선물·출장을 다음 행으로 배치한다.
- 패널의 중첩 세로 스크롤은 제거한다. 전체 페이지를 스크롤하되 탭을 고정할 경우 상단 HUD 바로 아래에 붙인다. 키보드 포커스가 고정 영역에 가리지 않게 한다.
- 대화는 화면 안쪽 12px 여백. 초상화 64×64 옆에 이름, 그 아래 본문과 선택지를 배치한다. 큰 글꼴·긴 선택지에서는 본문과 버튼 모두 줄바꿈을 허용한다.
- 기록은 접힌 ‘가게 기록’ 버튼으로 제공한다. PC에서만 보이게 삭제하지 않는다. 설정의 저장·마감·새 게임도 모바일에서 모두 접근 가능해야 한다.
- 안전 영역을 확보하고, 손가락을 댄 상태만으로 구매·출장·선택지가 확정되지 않게 한다. 드래그 종료를 클릭으로 오인하지 않는다.

| 주요 행동 / 해당 버튼 글자 | `#d9b477` / `#282022` |
| 긍정 / 주의·손실 | `#b2c998` / `#edb4a8` |

UI 색은 아트의 32색 제한과 분리한다. 경고는 색 + 아이콘 또는 단어로 표시한다. 본문 대비는 최소 4.5:1, 큰 글자·조작 경계는 3:1을 목표로 구현 단계에서 실제 합성 배경까지 검사한다. 비활성 버튼은 사유를 따로 남긴다.

한글 픽셀 글꼴 후보는 **Galmuri11**이다. 제목·짧은 상태표에 우선 적용하고, 긴 대사·장부·설정에는 **Noto Sans KR** 14~16px를 권장한다. 숫자는 고정폭 숫자를 사용한다. 글꼴 파일과 라이선스는 이번 산출물에 포함하지 않았다. 배포 시 공식 라이선스와 한글 글리프 범위를 확인하고 자체 호스팅한다. 목업은 환경에 설치된 Noto Sans/Serif CJK KR로 렌더링했다.

## 9. 원본 인물 → 새 아트 기준

`assets/ref/ref_A.webp`~`ref_E.webp` 다섯 장을 직접 확인했다. 이 파일들은 참고 전용으로 유지했다. 사진·참고 그림을 축소하거나 필터를 씌워 게임에 사용하지 않았다. 생성한 시트는 새 그림이며, 목업은 이 시트만 사용한다.

| 코드 | 최우선 식별 요소 | 작은 스프라이트에서 남길 것 |
|---|---|---|
| A 레이나 | 긴 연금발, 녹안, 일자 앞머리, 땋은 머리, 눈 밑 점, 엘프 귀 | 연금색 긴 실루엣 + 녹색 롱스커트 + 옆으로 뻗은 귀. 땋은 머리·점은 정면 기준 화면 오른쪽 |
| B 네르 | 주황 단발, 고양이 귀, 금안, 송곳니, 긴 꼬리 | 머리 위 삼각 귀 + 주황 꼬리 + 갈색 앞치마·남색 반바지 |
| C 세르피나 | 적갈색 하이포니테일, 회안, 금장 남색 제복, 네모 녹색 브로치 | 높은 묶음머리 + 어깨 금장 + 검은 바지. 갑옷·치마로 바꾸지 않음 |
| D 이브레아 | 흑발, 보라 눈, 둥근 안경, 보라 카디건 | 둥근 안경 2점 + 긴 검은 머리 + 늘어진 보라 소매 |
| E 카샤 | 갈색 피부, 은백발, 반쯤 감은 호박색 눈, 금 꽃 귀걸이 | 피부/은발 대비 + 붉은 옷 + 흰 숄. 엘프 귀·검은 허리띠 |

전연령 기준에 맞춰 레이나는 흰 블라우스로 가슴을 덮고, 카샤는 목선이 높은 붉은 의상과 흰 숄로 재해석했다. 인물의 피부색과 핵심 색 조합은 유지한다. 사장 P는 기존 데이터의 갈색 머리와 수수한 회보라 작업복을 기준으로 한다.

### 현재 시안에서 확인한 수정 사항

인물 시트는 **분위기·색 분리 검토용**이다. 그대로 잘라 생산 스프라이트로 쓰지 않는다.

1. 워킹 예시는 3포즈이며 정면/옆면이 섞였다. 엔진 요구인 정면 4프레임(정지/걷기/정지/걷기)으로 다시 제작해야 한다.
2. 레이나의 작은 포즈 일부에 고양이 귀처럼 보이는 돌출이 생겼다. 제거하고 귀는 옆면의 엘프 귀만 유지한다. 레이나 눈 밑 점도 최종 64px에서 확인한다.
3. 세르피나의 작은 하체가 치마·반바지처럼 보인다. 검은 긴 바지와 장갑을 명확히 그린다.
4. 시트의 네르 꼬리·카샤의 긴 머리는 프레임 폭 16px 안에서 이웃 프레임을 침범하지 않도록 새로 설계한다.
5. 큰 초상화의 부드러운 음영과 세부를 줄여 실제 64×64 그리드, 약 32색으로 정리한다. 현 생성물은 이 요건을 충족하지 않는다.
6. 현재 시트 배경은 불투명이다. 게임용 개별 PNG는 투명 배경으로 다시 제작해야 한다.

### 배경 제작 기준

현재 실내 시안은 분위기 검토용이며 세부 가구·방 경계가 엔진 좌표와 정확히 일치하지 않는다. 최종 배경은 384×216에서 새로 맞춘다. 접수 `(8,8,122,52)`, 대기 `(8,68,122,140)`, 시술실 `(140,8)/(262,8)/(140,80)/(262,80)` 각각 `114×64`, 조향 `(140,152,114,56)`, 계단 `(262,152,114,56)`.

베드는 각 시술실 `(x+40,y+22,44,20)`을 따른다. 방 하단 `y+h−8`의 4px 진행 바 영역을 비운다. 미개설 방도 그림은 완성하고 마스크는 엔진에 맡긴다. 인물·상태표·글자를 배경에 굽지 않는다. 야간 배경은 가구 위치와 통행 경계를 그대로 유지하며 등불과 실내 색만 바꾼다.

## 10. 게임용 에셋 제작 대기표

아래는 **제작해야 할 목록**이며 완료 목록이 아니다. 파일명은 일반 소문자 권고보다 `assets/manifest.js`의 실제 경로를 우선하므로 P·A~E는 대문자를 유지한다.

| 경로 | 수량·규격 | 현재 상태 |
|---|---|---|
| `assets/sprites/char_P.png`, `char_A.png`~`char_E.png` | 6장, 각각 64×24, 16×24 정면 4프레임 | A~E 디자인 시안만 있음. P 미제작 |
| `assets/sprites/cust_{human,elf,beast,dwarf,dragon}_{f,m}.png` | 10장, 각각 64×24 | 미제작 |
| `assets/sprites/face_A_2.png`~`face_E_2.png` | 5장, 각각 64×64, 평소 표정 | 고해상도 인물 시안만 있음 |
| `assets/bg/floor1.png`, `floor1_night.png` | 2장, 각각 384×216, 불투명 | 주간 분위기 시안만 있음. 야간 미제작 |
| `assets/ui/icons.png` | 1장, 128×16, 8셀 | 미제작 |

우선순위는 평소 초상화 5장 → P·A·B 워킹 → C·D·E 워킹 → 낮 배경 → 손님 10장 → 밤 배경·아이콘이다. 이후 기쁨 3 / 당황 5 / 분노 7 / 지침 10 표정으로 확장한다. 아이콘 순서는 스펙 본문의 **동전·평판·소문·향유·결·시계·피로·하트**를 사용한다. manifest의 짧은 아이콘 주석은 목록이 불완전하므로 따르지 않는다.

생산 에셋 검수는 원본 해상도·알파·프레임 셀 경계·발밑 1px 여백·정면 방향·식별 요소·약 32색·검은 외곽선 금지·정확한 경로를 모두 확인한다. 1배와 3배에서 각각 보고, 4프레임 재생 중 발바닥과 머리 위치가 불필요하게 튀지 않는지 확인한다. 시안 파일의 리사이즈만으로 ‘완료’ 처리하지 않는다.

## 11. Claude 구현 우선순위

**꼭:** 기존 6탭과 모든 조작 보존, 상시 속도 조절, 정수 배율 현장, 직원 빠른 배치 연결, 대화 가능 여부·비활성 사유, 직원/손님 행동 구분, 원문 대화·선택지 보존, 모바일 폭 대응, 저장·초기화 피드백, 키보드 모달 포커스.

**있으면 좋음:** 탭별 스크롤 기억, 현장 방 선택으로 해당 정보 강조, 관계 필터, 로그 유형 필터, 배치 변경 완료 강조, 픽셀 아이콘. 신규 관계 규칙이나 자동 직원 배치 기능을 이 작업에 추가하지 않는다.

구현 순서는 HUD·6탭·반응형 골격 → 기존 기능 연결 → 직원·관계 카드 → 모달 → 검증 → 규격 아트 교체다. 이 문서의 PNG는 디자인 참고 자료다. 실제 UI를 하나의 큰 이미지로 붙이지 않는다.

## 12. 검증과 남은 확인

이번 목업은 Chromium에서 데스크톱 1360px, 모바일 390px 너비로 렌더링했고 PNG로 저장했다. 이미지 로드 성공과 문서 가로 넘침 여부를 확인했다. 게임 코드·기존 참고 에셋에는 변경을 가하지 않았다. **PNG는 정적 시안이므로 버튼 작동·세이브·시뮬레이션 회귀 검증을 완료했다는 뜻이 아니다.**

Claude의 실제 구현 이후에는 360/390/768/1360px, 긴 가게 이름, 관계 0/100, VIP 미해금, 시술 중 직원, 향유 0개, 돈 부족, 긴 선택지, 모달을 닫은 뒤 원래 속도, 저장 복원, 마감·새 게임을 확인한다. 모바일 360px에서는 현장 내부만 가로 스크롤되고 페이지는 넘치지 않아야 한다.

Claude에게 메모: `src/data/characters.js`의 오래된 헤더 주석은 GPT에게 텍스트 작성을 안내하지만, 이번 작업은 최신 `GPT_BRIEF.md` 역할 분담을 우선했다. 이미지 모델의 출력은 현재 정확한 네이티브 해상도와 프레임 구조를 보장하지 못하므로 생산 에셋 검수가 별도로 남아 있다.
