## 1. 이전 접근 폐기

가게 그림을 웹 대시보드 안에 넣는 구성을 폐기한다. 가게와 인물이 화면을 채우고 작은 도트 HUD·도구띠·게임 창이 그 위에 붙는다. **화폐, 아이템, 창, 버튼, 막대, 포커스, 글꼴까지 같은 픽셀 규칙을 적용한다.**

- 플레이 화면의 **‘골목 시술소’ 제목, 한자 ‘結’, 영문 부제와 브랜드 영역 전부 제거**. 브리프의 가게 이름 상시 표시보다 이번 사용자 요청을 우선한다. 이름 데이터와 설정 내 편집 기능은 유지한다.
- 고정 오른쪽 대형 패널, 넓은 웹 여백, 영문 섹션 제목, 대시보드 수치 카드와 긴 세로 페이지 제거.
- 금화·은화·동화는 서로 다른 도트 아이템으로 제작. 단위 글자와 이모지만으로 대신하지 않는다.
- 장부·망치·향유병·관계 편지·톱니도 같은 아트로 제작. 기본 HTML 버튼이나 벡터 아이콘을 섞지 않는다.
- 평소에는 현장을 크게 보고 관리할 때 창을 연다. 닫으면 곧바로 현장이 중심이 된다.

## 2. 기본 플레이 화면

상단 왼쪽은 지갑, 평판·소문, 오른쪽은 날짜·시각·정지·1×/2×/4×다. 하나의 큰 웹 헤더 대신 작은 나무 프레임 묶음을 사용한다. 중앙에는 접수·대기·시술실·조향실·계단과 이동 인물이 보인다.

하단 중앙은 여섯 칸 도구띠다. **장부=가게 / 인물=직원 / 망치=확장 / 향유병=향유 / 하트 편지=관계 / 톱니=설정**. 아이콘 밑에 짧은 한글을 붙이고 선택한 칸에 황동 테두리를 표시한다. 왼쪽은 직원 얼굴과 피로, 오른쪽은 향유 재고 바로가기다. 로그는 알림 한 줄만 잠시 표시하며 전체 기록은 장부에서 연다.

### 기존 캔버스 연결

세계는 **384×216**과 `ASSET_SPEC.md`의 방·베드·진행 바 좌표를 유지한다. 시안의 방 그림을 새 좌표로 취급하지 않는다.

실제 기본 게임 표면은 논리 **384×264**를 제안한다: 위 HUD 20px + 세계 216px + 아래 도구띠 28px. 세계 밖 띠도 같은 목재·보라 그림자로 연결한다. 이렇게 하면 HUD 때문에 접수대와 진행 바를 가리지 않는다. 관리 창은 세계 위에 뜬다.

PNG는 전체 분위기를 보여 주기 위해 16:9에 겹쳐 배치한 아트다. 구현에서는 위 논리 규격을 기본으로 정수 배율 확대하고 남는 영역을 짙은 배경으로 채운다. 세계를 늘리거나 방 좌표를 재설계하는 작업은 이번 UX 개편에 포함하지 않는다. 터치 영역과 큰 글자는 별도로 확보한다.

## 3. 공통 픽셀 규칙

| 요소 | 규칙 |
|---|---|
| 격자 | 원본 1px 정렬, 최근접 정수 배율. 흐린 보간 금지 |
| 창 | 어두운 1px 외곽선 → 밝은 목재 1px → 짙은 내부. 2px 계단 모서리. 9-slice 모서리는 늘리지 않음 |
| 표면 | 나뭇결은 가장자리 위주. 글자 뒤는 평평한 짙은 바탕 |
| 버튼 | 기본/포커스/누름/비활성 4상태. 누름은 안쪽 그림자+내용 1px 이동. 둥근 캡슐·블러 그림자 제외 |
| 막대 | 같은 어두운 홈과 테두리. 관계/피로/시술 진행은 이름과 수치로 구분 |
| 아이콘 | 16×16 기본, 아이템 상세 32×32 별도 제작. 좌상단 광원과 외곽선 공유 |
| 숫자 | 고정폭 픽셀 숫자. 자릿수가 늘어도 HUD 위치 유지. 툴팁에 전체 값 |
| 글자 | 짧은 HUD와 버튼은 한글 픽셀 글꼴. 제목용 세리프·영문 장식 제거 |
| 포커스 | 밝은 황동 1px 안쪽 선+선택 표시. 호버만으로 상태 전달하지 않음 |
| 효과 | 픽셀 1~2단계 밝기 변화. 유리 효과·부드러운 광택·그라데이션 제외 |

팔레트: 외곽선 `#211c29`, 그림자 `#382a32`, 목재 `#704b3b`, 밝은 목재 `#a57950`, 금 `#d7ac62`, 글자 `#eee1bc`, 긍정 `#91ad74`, 손실 `#c97868`. UI와 배경이 같은 계열을 쓰되 글자 대비는 더 높인다. 32색 내외는 생산 목표이며 현재 생성 이미지의 충족을 뜻하지 않는다.

글꼴 후보는 Galmuri11. 배포 라이선스·글리프 범위는 도입 시 확인한다. 작은 시스템 글꼴로 흉내 내고 최종 완료 처리하지 않는다. 큰 글자 모드에서는 읽기 쉬운 크기를 우선하되 창·아이콘 아트는 유지한다.

## 4. 화폐·향유

금화는 황동색, 은화는 회청색 테두리의 은색, 동화는 붉은 갈색. 각인과 테두리 패턴도 다르게 만들어 색 없이도 구별한다. 셋 모두 16×16에 좌상단 광원으로 그린다.

HUD는 `[금화 그림] 12 [은화 그림] 4 [동화 그림] 30` 형식이다. 고정 수치가 아니라 기존 금액 변환 결과를 넣는다. 동화 잔액도 누락하지 않으며 접근성 이름에는 단위를 포함한다. 수입·가격 아이콘도 수치 단위와 맞춘다. **동화 240 수입을 금화 그림+240으로 표시하면 안 된다.**

진정은 둥근 녹색 병+잎, 온열은 긴 호박색 병+불꽃, 월하향은 보라색 병+초승달로 제안한다. 색뿐 아니라 실루엣과 표식으로 구분한다. 향유 창은 아이템→이름·재고→1병/5병 구매 순서로 읽는다. 버튼마다 실제 가격을 붙인다. 재고 0, 돈 부족, 미해금은 다른 상태다.

월하향 미해금에는 잠금과 실제 조건을 표시한다. 조향실은 증류기·담당 얼굴로 표시하며 빈 담당에는 ‘배치 없음’과 직원 창 연결을 제공한다. UI 때문에 새로운 재료·조합법·등급을 만들지 않는다.

## 5. 관리 창으로 옮길 기존 기능

같은 테두리·버튼·스크롤 손잡이를 공유한다. 창은 하나를 기본으로 하고 다른 도구띠를 누르면 내용을 전환한다. 닫기는 오른쪽 위에 고정한다.

| 진입 | 게임 창 | 보존 기능 |
|---|---|---|
| 장부 | 내부 책갈피가 있는 장부 | 오늘 수입·지출·시술·이탈, 방·대기, 단골, 메뉴 4종, 다음 목표 4개, 7일 장부, 전체 로그 |
| 직원 | 얼굴 선택띠+선택 직원 상세 | 능력치 4, 특성, 피로·경험, 접수/조향/시술/휴식, 지원자 3명, 고용·해고 |
| 망치 | 확장 도면 | 14종 효과·비용·잠금·구매·완료 |
| 향유 | 아이템 슬롯 창 | 재고·1병/5병 구매·월하향·조향 담당 |
| 편지 | 얼굴 선택띠+선택 인물 | A~E, 관계 값·단계·설명·훅·퀘스트, 대화·선물·출장 |
| 톱니 | 작은 설정 창 | 이름 편집, 저장, 마감, 새 게임, 누적 통계 |

관계는 다섯 개의 큰 웹 카드 대신 작은 얼굴 선택띠와 한 명의 상세를 보여 준다. 직원 A·B는 대화/선물, 손님 C·D·E는 대화/선물/출장을 유지한다. 가능 표시와 비활성 사유는 실제 엔진 판정을 사용한다.

대화는 하단 도트 대화 상자+선택지 창으로 제안한다. 인사→주제→답변→반응, 원문 대사, 답변 시 횟수 소모를 유지한다. 강제 선택과 일반 창의 닫기·시간 진행 정책을 구분하고 기존 이벤트 생명주기를 보존한다.

세르피나·이브레아·카샤는 손님이다. 직원을 늘려 보이게 하려고 이들을 시술 직원으로 그리지 않는다. 외형은 `assets/ref/ref_A.webp`~`ref_E.webp`가 우선이며 이전 생성물의 귀·의상 오류는 따라 그리지 않는다.

## 6. 모바일·조작

모바일도 현장+얇은 HUD+하단 도구띠를 기본으로 한다. 관리 창은 현장 위 시트로 열고 닫으면 같은 카메라 위치로 복귀한다. 긴 카드 웹 페이지로 바꾸지 않는다.

- 터치 영역 최소 44 CSS px. 그림의 픽셀 크기와 별도로 클릭 영역을 확보한다.
- 384px 미만에서는 현장 내부 이동 또는 가로 모드 안내. 문서 전체 가로 넘침 금지.
- 좁으면 화폐와 시간·배속을 두 줄로 나눈다. 전체 지갑을 펼칠 수 있게 하되 정지 버튼은 숨기지 않는다.
- 모든 창을 열 때 자동 정지하는 새 규칙을 임의로 추가하지 않는다. 대화·이벤트의 정지와 기존 속도 복귀는 현행 처리부터 검증한다.
- 툴팁은 키보드와 터치로도 접근한다. 모달 포커스를 관리하고 닫힌 뒤 원래 조작으로 복귀한다. 구매 중복 입력을 막는다.
- 버튼·제목·화폐 단위·재고를 접근성 트리에 제공한다. 최종 화면을 하나의 PNG로 붙여 구현하지 않는다.

## 7. 생산 에셋·Claude 인수

이번에는 전체 아트 방향을 개편했다. 게임 코드·대사·밸런스는 수정하지 않았다. 기존 `icons.png` 8셀에 금/은/동화와 메뉴·향유 변형까지 덮어쓰지 않는다. 아래는 **추가 생산 제안이며 아직 제작 완료된 파일이 아니다.**

| 제안 파일 | 규격 |
|---|---|
| `currency.png` | 48×16, 금/은/동화 3셀 |
| `menu.png` | 96×16, 장부/직원/망치/향유/편지/톱니 6셀 |
| `oils.png` | 48×16, 향유 3셀 |
| `window_frame.png` | 24×24, 8px 모서리의 9-slice |
| `button_states.png` | 96×24, 24px 셀의 4상태 |
| `slot_states.png` | 96×24, 기본/선택/빈 슬롯/잠금 |

기존 워킹 64×24, 초상화 64×64, 배경 384×216은 유지한다. 화면 시안에서 잘라내거나 축소해 생산 완료로 처리하지 않는다. 네이티브 에셋·알파·셀 정렬 제작 및 검수는 남아 있다.

구현 순서: 이전 웹 레이아웃 적용 중단 → 제목·브랜드 영역 제거 → 통합 표면·HUD·도구띠 → 공통 창·아이템 슬롯 → 기존 기능 연결 → 생산 아트 연결. 에셋이 아직 없다는 이유로 임의의 이모지나 다른 스타일을 최종안에 혼합하지 않는다.

## 8. 검수

이번 작업은 이미지 생성 도구로 새 화면을 만들고 저장하는 디자인 작업이다. 버튼·세이브·시뮬레이션을 구현하거나 테스트한 작업이 아니다. 생성 이미지의 가격·잠금·좌표보다 위 명세와 현재 코드가 우선한다.

최종 체크: ① 게임 제목·한자·영문 부제 없음 ② 도트 화폐·향유 ③ 배경·인물·HUD·글꼴의 픽셀 밀도와 광원 통일 ④ 닫으면 현장이 보이는 관리 창 ⑤ 기존 기능 보존 ⑥ 정지·닫기·주요 행동 접근 가능 ⑦ 기존 세계 좌표와 진행 바 보존.
