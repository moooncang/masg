# 06. 화면·저장·구현 순서·인수 검수

## 1. 클로드에게 전달하는 작업 지침

이 문서는 코딩 산출물이 아니라 기능 명세다. 기존 구현의 소규모 루프를 바탕으로 단계별로 확장한다. 기능 전체를 한 번에 교체하지 않는다. 현재 세계관과 에셋 좌표를 유지하며, 기능을 추가할 때 UI 설명·장부·저장 상태·실패 복구를 함께 완성한다.

v0.2의 성장 정본은07, 추가 콘텐츠는08이다. 02~04의 경제·운영 수치도 함께 개편되어 있으므로 v0.1의 전문화3종 표를 기준으로 구현하지 않는다.

개발 시작 순서: 이 문서의 P0 → 03의 경제 정본 → 04의 상태/처리순서 → 기존 `sim.js`·`state.js`·`ui.js`와 차이 확인. 아래 미구현 기능을 현재 데이터의 `effect` 키에 억지로 넣지 않는다. 엔진 변경이 필요한 항목임을 명확히 취급한다.

새 문서의 수치는 현재 코드와 다르다. 초기현금2,000→3,000, 초기 유지비500→기본300+창업급여300, 향유150/300→100/180, 품질등급의 대금배율 제거가 한 세트다. 이 중 일부만 적용하면 경제가 달라진다. 단계별 데이터 버전으로 묶고 중간 혼합 상태의 밸런스를 최종안처럼 평가하지 않는다.

## 2. 화면 구성

### 상시 상단

날짜·계절·시각 / 현금 / 오늘 예상 고정지출 / 최근 평가 / 명성 단계 / 소문 / 속도. 숫자를 누르면 원인을 연다. 상단에 연구·충성·재고 모든 숫자를 한꺼번에 넣지 않는다. 명성 막대는 다음 단계의 추가 조건을 함께 보여준다.

돈 표시 예: ‘보유 5금 / 예약금 1금 / 오늘 지급 8은 / 사용 가능 3금2은’. 예약 보증금이 투자 가능한 돈으로 보이지 않게 한다. 마이너스 상태는 색뿐 아니라 ‘미지급’ 텍스트로 구분한다.

### 중앙 1층/2층

384×216 논리 캔버스 유지. 1층은 기존 방 좌표, 2층은 지원실4슬롯으로 별도 설계한다. 기존 `floor2` 업그레이드의 효과만 바꾸면서 기존 배경이 저절로 생길 것으로 가정하지 않는다. 아트가 없으면 이름·상태가 있는 색 블록으로 먼저 검증한다.

방 위 아이콘: 사용가능 / 예약까지남은시간 / 시술진행 / 정리 / 청소필요. 직원을 선택하면 현재역할·남은작업·피로·다음예약. 손님을 선택하면 메뉴·고지가·예상대기·알려진취향·불만원인. 아이콘에 색과 짧은 글자를 같이 쓴다.

### 하단/우측 패널 7개

| 탭 | 기본 화면 | 추가 조작 |
|---|---|---|
| 오늘 | 미처리 경고3개, 수요예고, 지금 병목 | 영업 시작/신규접수 종료 |
| 서비스 | 활성6메뉴, 가격, 예상품질·기여이익 | 메뉴 편성·가격·현장/예약 허용 |
| 직원 | 역할/교대/피로/급여/자격 | 근무표·휴식정책·교육·고용·현장 지도 |
| 예약·단골 | 오늘 시간표, 할당자원, 단골 기억 | 예약 변경·알림·초대 |
| 시설·재고 | 방설비, 청결, 재고·할당·발주 | 공사·입고·자동발주 |
| 사람·의뢰 | A~E 관계, 단골·협업 이야기, 계약기한 | 선택·약속조회·계약수락 |
| 장부·설정 | 하루/7일 수익·거절사유, 저장 | 접근성·초기화·내보내기 |

성장은 ‘오늘’의 가게 성장 화면에서 명성·현재 인증·장기 프로젝트를 묶어 보여준다. 사장 운영법은 같은 화면의 정책 편성, 직원 자격은 직원 카드에 둔다. 모든 성장바를 상단에 늘어놓지 않는다. 공방은 자가/구매 원가와 향유 사용 예정일, 도제는 지도자와 학습자의 동시 점유 구간을 먼저 보여준다.

P0에서는 사용하지 않는 탭을 억지로 채우지 않는다. 단계별로 해금 후 표시하거나 ‘조건: 입소문’ 정도만 안내한다.

## 3. 핵심 화면의 정보 순서

### 고객 결과 카드

1. ‘시술 A / 만족 68 / 결제 360동’.
2. 품질: 실력+난도+숙련+시설-시작피로-청결±편차.
3. 만족: 편안함·설명·대기·가격·취향.
4. ‘아쉬운 점: 대기 32분(-11). 다음에는 예약을 권할 수 있습니다.’
5. 직원 성장·신뢰/충성 변동, 재방문 가능.

등급과 만족의 이름을 다르게 써서 A등급인데 단골이 안 된 이유를 알 수 있어야 한다. 수식은 ‘자세히’ 안에 두고 기본 화면은 가장 큰 원인 두 개만 보여준다.

### 가격 변경

현재가/새가격/고객군별 예산을 비교. 예상수요는 정확한 미래 예언이 아니라 현재 알려진 예산분포의 ‘높음/보통/낮음’과 범위. 적용 범위 ‘새 현장 접수부터’를 버튼 옆에 표시한다. 예약 가격은 변경되지 않는다고 관련 화면에서 명확히 알린다.

### 투자 비교

‘방 부족으로 놓친 손님 2명/일’, ‘직원 부족으로 놓친 손님 5명/일’, ‘3호실의 예상 회수24일’. 자금 부족일 때 버튼만 비활성화하지 말고 부족금액과 운영자금 공제 내역을 표시한다. 투자비 회수기간은 최근7일 기반이며 데이터3일 미만이면 ‘표본 부족’으로 둔다.

### 마감 보고서

요약 한 화면: 운영이익/현금변화/예약금잔액, 만족평균/이탈·거절, 직원 피로, 내일 위험. 다음 탭에 세부원장. 구매지출과 사용원가를 같은 비용항목에 더하지 않는다. ‘오늘 좋았던 것1개 / 개선할 것1개’를 실제 데이터에서 선정한다. 보유현금이 늘었어도 대출 때문이면 ‘수익 증가’라고 칭찬하지 않는다.

## 4. 알림과 편의 기능

- 긴급: 시술불가·예약충돌·지급 불능. 기본 일시정지. 확인 뒤 이전 속도로 복귀하되 사용자가 정지시킨 상태면 그대로 유지.
- 중요: 내일 납품 부족·3일뒤행사·계약만료. 사이드목록과 배지. 기본 정지하지 않음.
- 일상: 시술 완료·소액구매. 로그에 묶음 표시, 소리는 선택.
- 준비 단계에서 직원/서비스/예약/재고 네 영역의 경고를 한 번에 검토. 모든 경고가 해결되어야 영업 가능한 것은 아니다. 불가능한 확정예약만 강한 경고.
- 정보만 읽는 패널은 선택적으로 자동정지. 가격·교대 변경은 정지 중에도 가능하지만 이미 시작한 거래에는 소급하지 않음.
- 스페이스 정지, 1/2/4 속도, Esc 패널닫기. 입력창 포커스에서는 단축키 비활성.
- 모바일 최소44px 조작영역, 작은 픽셀글꼴 강요 금지. UI텍스트 배율100/125/150%, 모션감소, 효과음/배경음 개별 설정(사운드 제작은 P3).
- 모든 색상 경고에 아이콘/텍스트 병행. 호버 전용 설명은 터치로도 열 수 있게 한다.

저장 시점: 준비진입/영업시작/거래완료/사건 선택/예약 변경/정산완료/수동저장. 저장이 너무 잦으면 한 프레임에 묶되 확정선택을 먼저 보여주고 저장실패를 숨기지 않는다. 진행 중 시술의 남은시간·품질스냅샷도 필요하다.

기존 `masg_save_v1`은 덮어쓰지 않고 최초 이전 전 원본 복사·내보내기를 제공한다. 새 버전은 별도 키에 쓴다. 원본 보존과 이전 결과를 확인한 뒤 새 규칙을 시작한다.

기본 이전안은 다음으로 고정한다.

1. 가게 이름·현금·주요 인물 신뢰·기존 시설·완료 기록을 유지한다. 기존 `rep`를 새 명성으로 그대로 옮기고 이미 해금된 항목은 다시 잠그지 않는다.
2. 열려 있던 영업일은 진행 중 고객과 대기 고객을 추가 대금·경험치 없이 정리한다. 진행 중 방의 `oilUsed`로 확인되는 향유만 재고에 돌려준다. 완료된 고객의 향유나 대금은 건드리지 않는다. v1에는 예약금이 없으므로 고객에게 가상의 예약금을 환불하지 않는다.
3. v1이 영업 중이면 다음 날 준비로 옮긴다. 이미 마감한 저장은 v1의 `day`가 증가한 상태이므로 그 날짜의 준비로 옮기고 다시 하루를 더하지 않는다.
4. 과거에 지출한 v1 유지비500은 과거 비용으로 남긴다. 새 날 급여·유지비를 미리 냈다고 처리하거나 현금으로 돌려주지 않는다. 새 규칙의 일비는 새 영업일 마감에 한 번 청구한다.
5. 최근 평가70, 전문화 미선택, 신규 시스템 진행도0. 군숙련은 사장R1·레이나H1·그 외0으로 시작하고 기존 능력치는 유지한다. 기존 누적 실적이 어떤 서비스군인지 저장에 없으면 추정하여 과다 보상하지 않는다.
6. 기존 향유는 이전한 준비 날짜에 입고한 것으로 기록한다. 신규 필수 재료인 천은20개를 이전 지원품으로 한 번 지급하고 초기 무상재고 원가로 기록한다. 기존 음수현금은 그대로 보존하며 회생 안내를 표시한다.
7. 이전 고유ID와 원본 체크값으로 재실행을 구분한다. 임시 새 저장 작성→검증→활성 전환 순서로 처리하여 중단 후 재시도에서 향유나 지원품을 중복 지급하지 않는다.

이전 안내에는 ‘진행 중 하루는 추가 시술 매출 없이 종료하고 다음 준비 단계에서 시작합니다’와 정확한 반환 재료를 보여준다. 동의하지 않으면 원본 저장을 유지한다. 여러 슬롯 중 새 게임은 기존 저장을 읽지 않는다. 저장 내보내기에는 서버 비밀값이 없으며 사용자 텍스트를 HTML로 실행하지 않는다.

## 8. 밸런스 검수 계획

- 회전 운영: M01/M02/M03 중심, 가격0.95, 낮2블록, 교육보다 인력과 정리에 투자.

## 9. 아트·연출 발주 묶음

기존 파일명과 캐릭터 코드를 유지한다. 기존 규격의1차 필수는 캐릭터 걷기6장, 일반 손님10장, 평소 표정 초상화5장, 1층 낮 배경1장이다. 후속 표정은 기쁨·당황·분노를 사용한다. 기존 전연령 기조를 유지한다.

새 UI에는 청결·휴식·예약·재료 부족·단골 아이콘5종과 예약 시간표의 텍스트 상태가 필요하다. 후속 아트는 지원실8종, 계절 장식8개, 방별 설비3종의 중첩 가능한 오브젝트다. 2층 좌표와 아이콘 시트 확장은 아트 착수 전에 별도 ASSET_SPEC 제안으로 확정한다. 이번 문서는 기존 에셋 규격을 변경하지 않는다.

소리는 문종·장부·병·발걸음·빗소리로 분위기를 만든다. 시술 완료음은 짧게 만들고4배속에서 연달아 겹치지 않도록 제한한다.

## 10. v0.2 추가 비교 기준

새 정책은 현금이익만으로 비교하지 않는다. S04는 향유1병의 재료비·검사비·생산 직원분·폐기율을, S05는 지도 한 건의 총 인분·포기한 시술·군숙련 상승·자격 취득일을 기록한다. 성장 보너스를 넣고 지도자가 동시에 영업하는 잘못된 자동 검수는 무효다.

5전문화×30개 시드×60일은150개 실행의 개발 검수 계획이며 이번 문서 작업에서 실행한 결과가 아니다. 각 정책의30일 운영이익과60일 해금·직원성장·미지급을 함께 본다. OP/자격 없이 가능한 기본 운영과 장착 후 운영을 구분하고, 장기 프로젝트 지출 전후의 손익을 따로 비교한다.
